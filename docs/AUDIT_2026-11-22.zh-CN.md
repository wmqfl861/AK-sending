## 1. 总体结论

**核心工程质量很高，风险已经从“代码对不对”转到“产品能不能用、能不能发”。**

- 安全与正确性底座扎实：直连红线有 CI 与依赖黑名单把关；对端身份靠自签 Ed25519 证书加指纹钉扎，默认客户端配置拒绝一切未钉扎连接；收文件有逐组件的路径校验、符号链接与替换检测、不覆盖提交、分块摘要与续传；注册服务器有分层限流与容量上限。
- 测试与 CI 覆盖面在同类项目里少见：Linux 与 Windows 全量测试、macOS 可移植性检查、NAT 网络命名空间矩阵、Android 交叉编译与符号校验、cargo audit / deny、契约检查。
- 但 v1 还发不了，原因主要不在代码：
  1. 所有者事项（生产部署、签名、许可证、物理双机、Android 后台策略、移动数据）已经卡了十天左右，期间多个批次以复测与走查为主；
  2. 核心交互“把一个 44 个字符的码告诉对方”在跨设备场景下很难用，局域网发现能力没有进图形界面；
  3. 界面仍是开发态：应用名是 `ak_sending_app`、图标是 Flutter 默认图标、错误直接显示异常原文；
  4. 流程文档的维护成本已经超过它带来的收益。

建议的方向：**接下来两到三批把重心从“再验证一遍”转到“补齐产品体验”，同时请所有者集中做一次决定（§6）。**

## 2. 做得好的地方（保持）

- **红线落到了机制上，而不只是文档**：`deny.toml` 封禁 relay/TURN 类 crate，`check_repository.py` 扫 `Cargo.lock`，`config/architecture.json` 有结构校验，服务器协议里没有任何文件数据消息。
- **身份与传输层**：`ak-net/src/tls.rs` 三个校验器分工清楚（钉扎客户端、拒绝一切的默认客户端、只认自签证书的服务端加逐指纹授权），QUIC 关闭主动迁移并在连接上监视远端地址变化。
- **收文件路径**：`ak-core` 的 `validate_rel_path` 平台中立、逐字符拒绝控制字符，Windows 特有规则单独在接收端执行；`ak-storage` 逐级确认真实目录、打开分片前复验、用文件身份检测替换、提交不覆盖，局限（没有 openat2）在注释里如实写明。
- **证据纪律**：模拟、同机、真机分开标注，结论与数字对不上时会被复核拦下（U-N1 就是例子）。
- **拆分重构有记号级证明**（CR-P2-08 的 `scripts/tokcmp`），纯移动可以被机器验证。

## 3. 发现

优先级：P1 阻碍 v1 或会让用户丢失对状态的判断；P2 明显影响体验或发布质量；P3 改进项。编号 AUD-xx 只在本文使用；需要排进批次的，在状态表里登记为 V-N 或 W 行。

### 3.1 产品与交互

**AUD-01（P1）配对码太长，跨设备几乎只能复制粘贴。**
`AKI1-XXXX-…-XXXX` 共 44 个字符（160 位密钥）。同一个人在两台自己的设备之间还能借助剪贴板同步，但电脑与手机之间、或两个人之间，用户要手抄 36 个字符。首页按钮用了二维码图标，却没有二维码。
建议分两步：
- 短期（不改协议）：电脑端显示二维码，手机端扫码加入；码卡片上加“分享”（系统分享面板）。需要新增 `qr_flutter`（纯 Dart，显示）与一个扫码插件，按 ADR-002 走依赖审批（所有者事项 O-6）。
- 中期（改协议，需 ADR-003）：改用 PAKE（例如 CPace 或 SPAKE2）配合短码，参照 magic-wormhole：短码（如 `7-紫色-台灯` 或 6 位数字）只能在线猜一次，猜错即作废，因此短码也安全；服务器只转发 PAKE 消息，属于信令，不违反 ADR-001。这会把“码太长”从根上解决。

**AUD-02（P1）局域网发现没有进图形界面。**
`ak-discovery` 已有 mDNS 发现（CLI 的 `discover` 能用），但 GUI 的唯一入口是服务器配对码。后果：同一 Wi-Fi 下也必须经过注册服务器；注册服务器不可用时，GUI 完全不能传文件，与“本地可达时优先本地”的原则不符。
建议：首页加“附近设备”区，列出同网段设备；点一下发起配对，两端显示同一个 4–6 位校验码（基于双方指纹的 SAS）确认后建立连接。targetSdk 升到 37（Android 17）后需要的本地网络运行时权限（BACKLOG 的 CR-P2-03）要一并处理。

**AUD-03（P1，即 V-N2）长时间后台后出现“僵尸连接行”。**
V2-b：后台超过 QUIC 空闲上限后连接已断，宿主早已报错，但应用回到前台后，连接行一直显示在传输，观察窗内没有任何错误。用户无法判断传输已死。见 [V 复核 §2](REVIEW_2026-11-22-batchV.zh-CN.md#2-复核方登记的新问题)。

**AUD-04（P2，即 V-N4）错误直接显示异常原文，且文案错位。**
V2-d 界面显示 `发送失败：AkFfiException(AK_FAILED 2): transfer failed after connecting via …: stream failed: connection lost`，紧接着又显示“配对已闲置过久，请重新配对”——真实原因是连接中断，不是闲置。建议所有错误统一经一个映射函数输出“发生了什么＋怎么办”两句话，原文放进可展开、可复制的“详情”。

**AUD-05（P2）加入方要重复选择方向。**
契约（ffi-v2 §ak_task_start）写明“加入方得对侧角色”，但加入面板仍要求用户先选“发送/接收”才能点配对。这一步多余，选错还会失败。建议加入时不选方向，配对成功后明确告诉用户“对方将把文件发给你”或“你可以选择文件发给对方”。

**AUD-06（P2）配对之后离真正发文件还有好几步。**
现在的发送路径：生成码 → 选方向 → 等对方 → 连通测试 → 点“完成”回到首页 → 在“当前连接”里点进详情 → 选文件 → 发送。而且“方向在配对后固定，反向需要重新配对”。建议改成“先说要做什么”：首页两个大按钮“发送文件”“接收文件”，发送方先选文件再出码，对方加入并同意后自动开始（见 §4.3）。

**AUD-07（P2）接收确认信息不足。**
横幅只写“对方请求发送 N 个文件（共 X）”，对方名称显示为“对端设备”。用户在不知道内容的情况下点“接受”。建议横幅显示发送方设备名与前几个顶层名称（例如“照片、合同.pdf 等 12 项”）。“最近传输不含文件名”是持久化的隐私约定，与确认时显示名称不冲突。

**AUD-08（P2）缺少系统集成。**
- Android：没有“分享到 AK互传”（`ACTION_SEND`/`SEND_MULTIPLE`），这是手机上最常见的发文件入口；后台收到请求没有通知。
- Windows：不能把文件拖进窗口；最小化时收到请求没有系统通知；接收完成没有“打开文件夹”。
- 两端：传输中没有系统级进度（通知栏或任务栏进度）。

**AUD-09（P2）Android 后台策略未定（U-N2）。**
V2 已确认：后台或锁屏几秒内传输停住，30 秒左右回来能继续，超过约 60 秒连接断开、重发可续传，进程会被冻结。建议所有者选 A（v1 只承诺前台传输）并加两件小事：传输期间保持屏幕常亮（Activity 的 `FLAG_KEEP_SCREEN_ON`，无需新依赖）和明确的界面提示；v1.1 再用 Android 14 起的“用户发起的数据传输作业”（user-initiated data transfer job）或 `dataSync` 前台服务做后台传输。D3 的前台服务设计文档可直接复用。

### 3.2 发布就绪

**AUD-10（P1）品牌与发布元数据仍是模板。**
Android 应用名、Windows 窗口标题与版本资源、Linux 标题都是 `ak_sending_app`；启动图标是 Flutter 默认图标；`pubspec.yaml` 的描述是“A new Flutter project.”；`applicationId` 是 `dev.ak.ak_sending_app`——一旦上架就不能再改。名称与包名要所有者定（O-3、O-4）。

**AUD-11（P2）承诺的平台与实际不符。**
README 写“跨 Windows、macOS、Linux、Android、iOS”，仓库里没有 `ios/`、`macos/` 工程，Linux GUI 没有构建过。建议 README 与支持矩阵把 v1 写成“Windows 与 Android 图形界面，Linux 命令行”，其余标“计划中”。

**AUD-12（P2）Windows 交付形态。**
- 只有 zip，没有安装器、开始菜单项、卸载入口；V4 发现删除程序目录后 `%TEMP%\ak-stage.log` 留在原处。
- V3 的包从带未提交改动的工作区构建（版本行带 `-dirty`）。发布包应拒绝从脏工作区构建，除非显式放行。
- 身份目录是 `%USERPROFILE%\.ak-sending`，Windows 惯例是 `%APPDATA%`；找不到主目录时退回当前目录下的 `.ak-sending`，可能把身份写到意外位置。

**AUD-13（P2）生产服务器是单点。**
注册与 STUN 地址 `122.51.121.24` 写死在 CLI（`task_cli.rs`）与应用（`ffi_simple_transfer_service.dart`）两处；服务器同时在线连接上限 256；没有域名（CR-P3-03 未定）。服务器宕机时 GUI 全部不可用（与 AUD-02 叠加）。建议：先上域名并把地址集中到一处配置；容量上限按预期用户量重估；AUD-02 做完后局域网传输不再依赖服务器。

**AUD-14（P3，即 V-N5）Android 冷启动慢。**
V4 里 debug 构建在模拟器上要等很久才出首帧。debug 加模拟器不能代表真实体验，但要用 profile/release 构建量一次；若仍慢，查是否在主 isolate 同步做了 FFI 初始化或身份生成。

### 3.3 代码结构

**AUD-15（P2）Dart 服务层过重、命名易混。**
`lib/services/simple_transfer_service.dart` 有 2209 行，同时承担事件泵、连接表、同意窗口、进度换算；`lib/ui/service/simple_transfer_service.dart` 是同名的界面契约。建议把前者拆成 `event_pump`、`connection_registry`、`consent_tracker`、`progress_mapper` 四个文件，契约文件改名为 `transfer_contract.dart`；拆分仍按“纯移动＋测试名单不变”的办法证明。

**AUD-16（P2）两条产品路径并存。**
旧邀请码／配对簿／daemon 与 v1 一次性任务码并存，E1 已决定冻结旧模型。建议给删除定一个具体时间点（例如 v1 发布后的下一个版本），在 BACKLOG 写明，避免两套模型长期一起维护。

**AUD-17（P3）文件名的大小写与 Unicode 规范化。**
清单里同时有 `A.txt` 和 `a.txt` 时，发到 Windows 或 macOS（大小写不敏感）会在中途撞名；macOS 生成的 NFD 文件名发到 Windows/Linux 后与 NFC 名称不相等。建议接收端在清单阶段做一次大小写与 NFC 冲突预检（与现有 `windows_incompatible` 预检同一位置），提前拒绝或自动改名。

**AUD-18（P3）目录创建的竞态窗口。**
`ensure_real_dirs` 在 `create_dir` 失败与 `symlink_metadata` 之间有窗口，注释已承认。要利用它，攻击者需要能写接收目录，风险低。长期可改为基于目录句柄的操作（Linux/Android 的 `openat2` + `RESOLVE_BENEATH`，或 `cap-std`），作为加固项。

**AUD-19（P3）私钥保护。**
Unix 上身份文件是 0600；Windows 依赖用户目录的继承 ACL；Android 在应用私有目录且已排除备份。可选加固：Windows 用 DPAPI、Android 用 Keystore 包一层。

**AUD-20（P3）事件轮询。**
活动期每 50 ms 轮询一次原生事件，已有门铃（`ak_task_set_event_notify`）兜底。门铃稳定后可把活动期轮询放宽到 250 ms 以上，省电。

## 4. 界面设计方案

### 4.1 设计原则

1. **先说要做什么，再处理怎么连**：用户想的是“发文件给他”，不是“生成配对码”。
2. **一屏一件事**：每一步只有一个主要按钮。
3. **状态诚实且可行动**：任何失败都说明发生了什么、用户现在能做什么；不显示异常原文。
4. **少术语**：界面里不出现“对端”“任务”“连通测试”“直连失败”这类工程词，用“对方”“连接”“检查网络”。
5. **安全感可见**：显示“文件不经过服务器”“已加密直连”，但不让用户做安全决策。

### 4.2 信息架构

两个一级入口不变，改名并重排内容：

| 入口 | 内容 |
|---|---|
| 传输（原“连接”） | 两个主按钮“发送文件”“接收文件”；附近设备（AUD-02 之后）；进行中的传输；最近传输 |
| 设置 | 保存位置；关于（版本、服务器版本、“文件不经过服务器”说明）；连接诊断导出 |

宽屏（≥ 1000 px）改为左右两栏：左栏是“传输”首页，右栏显示选中传输的详情，不再整页跳转。

### 4.3 关键流程

**发送方（主路径）**

```
[发送文件] → 系统选择器（文件或文件夹，可多选；桌面可直接拖入）
          → 码卡片：大号分组码 + 二维码 + 复制/分享
                    “把这个码给对方，对方输入后会收到你的文件”
                    已选：12 项 · 340 MB   [更改]
          → 对方加入：“已连接到 小王的手机，等待对方接受…”
          → 进度卡片：总进度、速度、剩余时间、当前文件；[取消]
          → 完成：“已发送 12 项（340 MB），用时 2 分 10 秒”  [再发一些] [完成]
```

次要入口：“对方已经给了你一个码？[输入对方的码]”。

**接收方（主路径）**

```
[接收文件] → 输入码（大字号、自动分组、粘贴即识别）或 [扫描二维码]（手机）
          → 确认卡片：“小王的电脑 想发送 12 项（340 MB）：照片、合同.pdf …”
                      保存到：下载/AK互传   [更改]
                      [接受]  [拒绝]   剩余 118 秒
          → 进度卡片 → 完成：[打开文件夹] [完成]
```

次要入口：“想让对方输入你的码？[生成接收码]”。

两条主路径都不再出现“选择方向”的步骤；方向由用户点的按钮决定。v1 的“一码一次、恰好两方”不变。

**失败与恢复**

| 情况 | 标题 | 说明 | 按钮 |
|---|---|---|---|
| 码无效或过期 | 这个码用不了 | 码可能输错了或已过期（10 分钟有效），请让对方重新生成 | 重新输入 |
| 两端无法直连 | 无法直接连接到对方 | 两台设备的网络都不允许外部连入。连同一个 Wi-Fi 通常就能解决。文件不会经过服务器中转 | 再试一次 · 查看帮助 |
| 传输中断 | 传输中断了 | 连接在 X 时断开（例如应用在后台太久）。已传的部分会保留，重新发送会从断点继续 | 重新发送 |
| 对方拒绝 | 对方没有接受 | — | 完成 |
| 保存位置不可写 | 无法保存到所选文件夹 | 请换一个文件夹，或在系统设置里允许访问 | 更改文件夹 |

每张失败卡片下方有“详情”可展开，显示错误码与原文，并可复制，用于反馈问题。

### 4.4 视觉规范

- **颜色**：保留品牌色 `#316A5A` 作为 Material 3 种子色；成功、警告、错误各定义一对前景色／容器色，深浅主题分别取值（成功色已有，补警告色）。
- **字体**：配对码用等宽字体并显式给出回退列表（`Cascadia Mono`、`Consolas`、`Menlo`、`Roboto Mono`、`Noto Sans Mono`），因为 Flutter 在 Windows 上不保证能解析通用的 `monospace`；码按 4 位一组，组间留空，字号 28–32。正文不再写死 `fontSize: 18`，一律用主题的文字样式，以便跟随系统字号。
- **布局**：手机单栏，左右 16 dp 边距；主按钮高 56 dp、圆角 16；卡片圆角 16、内边距 16–20；宽屏两栏，左栏固定 360–420 px。
- **进度**：线性进度条加“已传 / 总量 · 速度 · 剩余时间”一行；校验阶段换成不确定进度条加“正在校验完整性”。
- **空状态**：首页无传输时，用一个图标加一句话说明两种用法，不放大段说明文字。
- **图标**：首页主按钮用 `upload_rounded` / `download_rounded`；二维码按钮只在真正有二维码时出现。

### 4.5 文案规范

| 统一用 | 不再用 |
|---|---|
| 配对码（界面）／任务码（仅工程文档） | 混用；README 的 v1 章节对用户的部分改为“配对码” |
| 对方 | 对端、对端设备 |
| 连接 | 配对（在“建立连接”的意义上） |
| 无法直接连接 | 直连失败、不可达 |
| 正在检查网络 | 正在测试连通性 |

句式：标题说结果，正文一句说原因、一句说怎么办；按钮用动词（“重新发送”“打开文件夹”），不用“确定”“知道了”。

### 4.6 平台细节

- **Android**：分享入口（`ACTION_SEND`/`SEND_MULTIPLE`，带 `content://` 读取授权）；传输中保持屏幕常亮；收到请求时发通知（需要 Android 13 起的通知权限）；后台传输按 AUD-09 分阶段。
- **Windows**：窗口标题与图标；拖放；系统通知；完成后“打开文件夹”（`explorer /select,`）；安装器（AUD-12）。
- **无障碍**：所有图标按钮有提示文字（现有大部分已有）；进度与倒计时用 `Semantics` 的 live region 播报；在系统字号 200% 下检查不溢出；颜色之外始终有图标或文字区分状态。
- **国际化**：用 Flutter SDK 自带的 `gen-l10n`（`flutter_localizations`，不属于第三方依赖）把字符串集中到 `.arb`，先只有简体中文，为英文版留口。
