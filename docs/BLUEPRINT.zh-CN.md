## 1. 产品定义与范围

AK互传是 Windows、macOS、Linux、Android、iOS 五端主动文件互传工具。第一版覆盖自己明确配对的设备，后续版本扩展到其他用户。

| 必须保留的需求 | 定义 |
|---|---|
| 局域网优先 | 验证真实路径与设备身份，优先本地 Wi-Fi、有线或热点，不以 SSID 或公网出口相同判定 |
| 互联网 P2P | 仅最终两端直连；失败则暂停、等待或重试，没有中继兜底 |
| 服务器只协调 | 仅设备发现、在线状态、信令、地址发现和 NAT 穿透协调 |
| 不限速、大小、类型、总数量 | 不设置商业限速或产品额度；有限并发、内存背压不是文件总量限制；保留标准拥塞控制 |
| 完全不压缩 | 原始字节、不转码、不重新编码、不自动打包压缩；应用安装包压缩与用户文件传输无关 |
| 可设置保存位置 | 每设备默认位置、每次接收可询问、单任务可改选；尊重系统授权 |
| 轻量化 | 同时约束运行资源、安装体积、依赖、后台活动、服务部署及维护复杂度 |

首版支持普通文件、目录、空目录、批量追加、暂停与恢复、完整性验证、重名保留两份和可信设备授权接收。文件内容一致与 ACL、扩展属性、符号链接等跨文件系统语义分开承诺；不静默丢弃无法保留的对象或元数据。

双方必须同时在线且获得系统运行机会。接收方离线时队列留在本机，发送方继续持有源文件。第一版不做云端暂存、第三设备代传、后台永久保活、文件夹自动同步、网页接收、聊天、插件商城或多设备同时广播。局域网使用不强制注册账号。

## 3. 最终技术栈与工程结构

| 层 | 决策 | 边界 |
|---|---|---|
| 界面 | Flutter，Dart AOT release | 只负责交互、任务指令和节流后的进度事件；文件正文不经 Dart 复制 |
| 共享核心 | Rust | 身份、调度、目录清单、文件读写、校验、断点、网络和策略 |
| 数据连接 | quinn + rustls，QUIC/TLS 1.3 | 局域网与公网共用；不自行发明加密协议；首版禁用文件和授权操作的 0-RTT |
| NAT 穿透 | 成熟 STUN/ICE 检查组件 + 自有协调逻辑 | 使用标准事务、重传、候选检查与选路；不从零自研通用 ICE，不收集或接受 relay 候选 |
| 本地状态 | SQLite | 任务与文件清单分页、恢复检查点、目录授权引用；批量提交，不逐包写数据库 |
| 摘要 | BLAKE3 成熟实现 | 整文件增量摘要 + 恢复用块摘要；协议显式版本化，不自行组合摘要冒充标准整文件摘要 |
| 平台接口 | Swift / Kotlin / 必需桌面适配 | 原生发现、目录、文件句柄、相册原件、生命周期及密钥保护 |
| 协调服务 | 单个 Rust 可执行程序，逻辑分离信令与 STUN | 一个部署单元、不同 TCP/UDP 端口；不引入 Redis、消息队列、对象存储或微服务集群 |

工程边界先控制为 `ak-core`、`ak-transport`、`ak-transfer`、`ak-cli`、`ak-coordinator` 及 Flutter 客户端。平台代码放在客户端适配层；仅在责任边界需要时拆 crate，不按每个概念建立微服务或插件框架。

版本与 Cargo feature 在 M0 固定并提交锁文件；仅启用需要的 crypto provider 与平台特性。Flutter 覆盖五端是框架能力，不是项目已通过五端验收；保留它是减少五套 UI 维护的工程选择，不宣称其绝对最小或 Tauri 天生不适用。[R3][R7]

**必须早期解决的技术接缝：**STUN、连通性检查和 QUIC 在对应地址族/接口上复用同一 UDP 端点与有效映射，接收分流由一个受控适配器管理。禁止两个独立读取循环争抢同一 socket，也禁止 STUN 用 A 端口探测后 QUIC 任意改用 B 端口。quinn 的 socket 接口提供接入点，但不能替代该实验。[R3][R4]

## 4. 无服务器文件路径的强制边界

控制面只允许固定类型的设备身份、短期会话、候选地址、能力与握手协调信息。文件正文、密文块、可重构编码片段、文件名、目录清单、缩略图、内容摘要、块确认及断点明细全部只走认证设备直连。

信令采用有上限的结构化消息，不接受任意二进制 blob、通用 WebSocket 隧道、HTTP CONNECT、上传下载接口或代理目标。STUN 只实现所需 Binding 功能，不提供 TURN Allocate、Send 或 ChannelData。首版信令使用小型 JSON schema 即可；大小、候选数、重试与会话速率设资源上限，未知字段和非法状态拒绝。

服务端可见必要 IP 和在线时间等元数据，因此不宣传完全不可见。配对设备的长期公钥由终端保存并固定，服务端不能仅通过重写信令替换已信任对端；密钥变化必须重新授权。

文件引擎只能接收 `AuthenticatedDirectConnection` 与独立的 `ReceiveGrant`。二者只能由传输验证层、接收授权层分别生成，不提供由调用方填写三个布尔值的生产构造器。裸网络句柄不越过该边界；握手成功不等于用户同意接收。连接/路径 epoch、身份或授权变化使旧许可失效，暂停后重验。

类型封装是防误用机制，不是网络路径的密码学证明。依赖黑名单只能识别已列名称/特性，不能识别任意改名代理；必须结合源码边界、编译期负例、服务接口测试与双端/服务端抓包。普通路由器、NAT 和用户网络中不可见的透明设施按 ADR-001 的既有边界解释。

## 5. 发现、选路与穿透

本地发现使用系统 Bonjour/DNS-SD；Android 优先 NsdManager；桌面使用平台适配或经过审核的最小 mDNS 实现。二维码/手动地址始终保留为组播不可用时的补充。Apple 平台优先原生已声明服务类型，避免以自发组播扩大权限。[R8]

有互联网时，仅对已配对或明确授权的会话交换必要内网候选。同一出口 IP 只作为优化提示：CGNAT 下不同家庭也可能共用出口；同一局域网也可能有多个出口，不能以它作为必要条件或信任依据。不申请位置权限去比较 SSID。

选路步骤：

1. 收集本地候选、缓存地址和当前网络事件，验证端点身份与可达性。
2. 有界本地探测期间可并行准备公网，但文件正文等待本地结论；本地可用即采用。
3. 公网候选包含 IPv6、IPv4/STUN 映射、用户允许的端口映射；IPv6 优先、IPv4 有限并发，不因 IPv6 黑洞长时间串行等待。
4. 只选通过连通检查、TLS 身份验证和接收授权的路径；STUN 返回映射不算成功。
5. 全部失败进入等待直连，指数退避结合网络变化重试；不进行持续高频打洞。
6. 发现更优本地路径时，在安全检查点迁移或重连，复用任务 ID 和已验证块；不承诺底层迁移永远无感。

IPv6 仍受防火墙限制；NAT 映射有寿命，网络切换须重新检查。初版不同时实现 TCP 文件通道：禁 UDP 时明确报告该版本无法建立 QUIC 直连，而不是声称所有协议永远不可能直连。仅在实测收益充分、无中继验证通过后另行增加 TCP+TLS 直连适配。

可选端口映射默认关闭；仅可信家庭网络用户主动启用，申请本机所需 UDP 端口，使用短租约、活动时续期、结束时删除、异常退出靠租约到期回收，不创建永久映射或改动防火墙总开关。协议支持和实际公网可达性分别检查；上游 CGNAT 不保证被家庭路由器映射解决。[R5]

仅局域网模式不连接公网信令或 STUN。稳定直连不能因协调服务器退出而被应用主动断开；地址改变后若需要重新协调，明确进入等待而不是改走服务器。

## 6. 传输、校验与恢复

首版每个文件顺序传输，多个文件有限并发；初始并发目标手机 2、桌面 4，受全局内存预算约束。大文件初始块大小 4 MiB，可在实验后调整；64 位大小和偏移、溢出检测、分页清单。大量小文件复用连接与有限工作流，不为每文件建连接/线程，不要求先生成完整 ZIP。

发送端读取时计算 BLAKE3，接收端按顺序写入时计算 BLAKE3；完成后比较所选字节流的整文件摘要。正常连续传输不默认再读完整文件。传输加密负责网络通道完整性，应用摘要负责端到端文件结果比对，两者不互相替代。[R6][R11]

可靠检查点必须包含文件/任务版本、已可靠写入的范围、块摘要和提交状态。写盘完成、适用的同步成功后，再提交 SQLite 检查点并确认；文件系统和数据库并非同一个原子事务，启动恢复必须交叉核对。检查点按批次落盘，界面区分收到字节与可靠保存字节。

**恢复时允许且可能必须重读。**首版不序列化未稳定承诺格式的摘要内部状态；进程重启后重读并核验有效前缀以重建增量摘要，再继续。已验证持久化块不无故重传，但不承诺零磁盘重读。不得把独立块摘要简单拼接当成 BLAKE3(file)。后续仅凭实测收益考虑经过证明的树形校验协议。

保存先临时文件，再校验、同步、提交。可原子重命名的同目录目标使用安全提交；不支持的文件提供器使用可恢复流程。断电后确认实际目标状态，确保完成消息丢失后可幂等重发，不能生成重复完成文件。

保存抽象表示授权目标及能力：是否可寻址、随机写入、重命名、持久授权与空间查询。无法随机访问的提供器需顺序续传或用户明确同意的本地暂存，提前提示额外空间；不默认复制整个大文件两次。

源文件变化时停止该文件并重新确认版本。大小/时间戳仅作变化检测线索，不宣称它们证明快照一致性；活动数据库、虚拟机等应使用用户提供的稳定副本或系统可用快照，不自动上传备份。

接收路径拒绝绝对路径、`..`、目录逃逸和符号链接竞态；处理保留名称、大小写、Unicode 与长路径冲突，改名记录映射。默认不跟随符号链接，不自动执行收到的文件。

状态模型至少区分：待处理、扫描、连接、等待接收授权、传输、等待直连、暂停、校验、保存、完成、失败、取消。现有 `job.rs` 需增加授权状态；只有接收端确认最终保存后才显示完成。

## 7. 轻量化的可测预算

以下为首版**初始工程预算，不是已测结果，也不是对用户文件的额度**。M0/M1 建立指定设备与 release 构建基线，超预算必须提交实测原因和优化决定，不能偷偷放宽，也不能通过移除加密/完整性检查达标。

| 指标 | 初始目标 |
|---|---|
| 下载包 | 桌面单架构 ≤60 MiB；Android 单 ABI ≤40 MiB；iOS 按设备裁剪的下载估计 ≤60 MiB |
| 空闲内存 | 桌面进程树 RSS ≤180 MiB；Android PSS / iOS physical footprint 分别 ≤150 MiB，不混用测量口径 |
| 活动传输缓冲 | 全局总预算手机 ≤32 MiB、桌面 ≤64 MiB，包含应用队列与传输层窗口，不为每任务重复分配整份预算 |
| 空闲 CPU | 静态设备页、无任务的十分钟单核归一化平均 ≤1%；单独记录发现和重连瞬时峰值 |
| 启动 | 固定参考设备上十次冷启动 P95：桌面 ≤2 秒、手机 ≤3 秒；不以 debug 构建测试 |
| 后台 | 无任务不持有 wake lock、不维持高频扫描；桌面开机启动/常驻托盘由用户启用，手机不承诺永久接收 |
| UI 更新 | 进度聚合，默认每秒最多 5 次常规更新；列表虚拟化、文件清单分页 |
| 数据库与日志 | 批量事务、可清理缓存；日志有空间与保留期限，不记录文件内容、真实路径或凭据 |

包体同时记录下载大小和安装后占用，不用 APK/AAB/IPA/.app 的不同口径制造对比；Flutter 提供 release size analysis。[R7] 内存还须分别测运行时、SQLite 页缓存、平台提供器缓冲与网络队列，防止“只限制自己的 byte array”形成假达标。

默认不嵌浏览器内核、网页容器、媒体预览/转码引擎、大字体包或第三方常驻统计 SDK。核心直接处理文件句柄；移动端必要的平台流适配允许有限缓冲，不宣称所有来源都能零复制。

资源上限不是带宽配额。以拥塞控制、磁盘背压和固定资源预算驱动吞吐；高时延高带宽网络可能受到窗口预算限制，须报告取舍，不许把“无商业限速”写成“任何网络都跑满”。

## 8. 五端与移动风险

首版支持五类系统，先验证 Windows 11 x64、macOS arm64、Ubuntu 24.04 x64、Android arm64、iPhone arm64；它们是首轮测试设备选择，不是永久排除其他系统。M0 固定 SDK/最低版本/ABI，手机至少覆盖最低支持、后台 API 分界与目标 SDK 三类环境；未测组合不标已支持。

Windows/macOS/Linux 默认用户下载目录下 AKTransfer 子目录，用户可改选可写目录。Android 通用文件夹基线用 SAF 授权子目录并持久化 URI；MediaStore.Downloads 作为受控实验项，不在证明目录/重命名/恢复语义前另建第二套默认存储实现。不能简单把 content URI 当磁盘路径。[R10]

iOS 默认应用收件目录，在 Files 可见；自定义位置通过文件选择器和安全作用域授权，处理撤权与书签失效。相册必须取原资源而非预览/兼容转码，Live Photo 多资源明确处理；未下载的云端原件不能离线发送。用户自行选择云盘提供器可能触发系统同步，应明确告知，不能作为产品服务器投递后门。

Apple 本地网络权限在前台引导申请，声明固定 Bonjour 服务类型；Android 同时验证 NsdManager、网络绑定与目标 SDK 对应本地权限。当前官方文档对 Android 17/target 37 的本地网络权限已有明确要求，不能只照旧版 INTERNET 权限处理。[R8][R9]

Android 14+ 优先验证 UIDT；旧版采用符合限制的前台传输机制。不能照抄要求公网可用的示例网络约束，否则纯离线 Wi-Fi 可能根本不启动任务。必须验证任务被分配网络与直连 socket 的绑定。UIDT 不是永久后台接收权限，dataSync 服务也有时长限制。[R9]

iOS 26+ 验证 BGContinuedProcessingTask 延续用户发起的传输，低版本提供前台传输与可恢复中断。官方允许该任务使用网络，不等于项目 P2P socket 已在真机后台验证。任务终止、锁屏、低内存、过热、用户强制退出分别测试。[R8]

**最小移动实验与 M1 并行，必须在完整 UI 投入前完成或明确阻塞：**核心链接、直接 UDP/QUIC 收发、无外网局域网、目录持久授权、任务终止后恢复与最小 release 体积测量。

## 9. 配对、安全与隐私

设备长期密钥存入平台安全存储；以成熟签名/证书实现承载身份并固定已确认的公钥指纹。自签证书不是跳过验证的理由，必须验证握手持钥证明、预期端点和协议绑定。密钥轮换与撤销显式处理。

首版以二维码或足够熵的配对邀请和双方确认完成绑定；无摄像头设备可显示/输入完整邀请或通过可信途径核对指纹。不能用 6 位短码直接当密钥；需要短码体验时，只采用成熟 PAKE 与在线猜测防护，未完成安全验证不进入首版。

协调服务防设备枚举、候选滥用与反射：绑定会话双方、短期 nonce、过期时间、候选数量与探测速率，重放失效；不接受任意目标的通用探测代理。控制消息限速与文件商业限速无关。

默认本地诊断；上报仅明确同意的脱敏统计。手机后台通知、日志、崩溃报告不得泄露文件路径和配对密钥。安全与路径逃逸负例属于首版门槛，不能以“轻量”删减。

## 11. 验收与项目状态

必须同时证明：断外网 LAN 可用；局域网优先；文件内容相同；无中继负例；断网/重启恢复；目录权限与磁盘异常处理；轻量预算；五端真实互通。大文件与海量文件样本不是产品上限。

公网测量从连接请求开始计数，记录失败所处阶段和持续性；重复同一路由组合不能伪装为大量独立网络。受控网络可达与不可达场景要求确定性结果，真实互联网场景只报告实测比例，不复制他方“约 70%”作为承诺。

当前仓库仍只有策略、分块计算、状态机领域骨架。Claude 提交附带的日志记录 Rust 23 项单测和 clippy 修复后通过；本次查阅了日志，但没有在当前无 Rust 工具链环境重跑。真实网络、五端构建、后台和性能结果尚不存在。本次蓝图定稿不改变这些事实。

## 12. 一手资料与推论边界

以下支持技术事实；资源预算、范围和取舍是本次项目决策，不是来源给出的性能保证。资料查阅日期为 2026-11-02；依赖版本升级要重新验证。

- R1：iroh [Multipath 说明](https://www.iroh.computer/blog/iroh-on-QUIC-multipath)，原生协调与 relay 路径；[RelayMode::Disabled](https://docs.rs/iroh/latest/iroh/endpoint/enum.RelayMode.html)，可以禁用 relay，不表示内置穿透仍完整。
- R2：[RFC 8445](https://www.rfc-editor.org/rfc/rfc8445)，ICE 候选与检查。AK 排除其 relay 路径。
- R3：[quinn Endpoint](https://docs.rs/quinn/latest/quinn/struct.Endpoint.html)，单 UDP 端点与自定义 socket 接口；不提供本项目已实现穿透的证据。
- R4：[RFC 8489](https://www.rfc-editor.org/rfc/rfc8489.html)，STUN 是穿透工具，不是单独完整解决方案。
- R5：[RFC 6887](https://www.rfc-editor.org/rfc/rfc6887.html)，PCP 映射/租约；本项目选择默认关闭。
- R6：[RFC 9001](https://www.rfc-editor.org/rfc/rfc9001.html)，QUIC 使用 TLS、认证与 0-RTT 重放风险。
- R7：[Flutter 平台](https://docs.flutter.dev/reference/supported-platforms)及[体积测量](https://docs.flutter.dev/perf/app-size)，不据此声称实际包体已达标。
- R8：Apple [TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)及[持续后台任务](https://developer.apple.com/documentation/BackgroundTasks/performing-long-running-tasks-on-ios-and-ipados)，必须补项目真机证据。
- R9：Android [UIDT](https://developer.android.com/develop/background-work/background-tasks/uidt)、[前台服务超时](https://developer.android.com/develop/background-work/services/fgs/timeout)及[本地权限](https://developer.android.com/privacy-and-security/local-network-permission)。
- R10：Android [SAF](https://developer.android.com/training/data-storage/shared/documents-files)及[MediaStore](https://developer.android.com/training/data-storage/shared/media)。
- R11：[BLAKE3 Hasher](https://docs.rs/blake3/latest/blake3/struct.Hasher.html)，支持增量摘要；并不因此保证持久化状态可跨版本恢复。
- R12：[RFC 8831](https://www.rfc-editor.org/rfc/rfc8831.html)，WebRTC DataChannel 协议组成；不能据此断言其在所有场景必定更慢。
- R13：[cargo-deny bans](https://embarkstudios.github.io/cargo-deny/checks/bans/cfg.html)，依赖与特性约束；不作运行时行为证明。
