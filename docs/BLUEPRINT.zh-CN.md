# AK互传项目蓝图 v0.1（纯直连修订版）

状态：产品架构已确认；实现处于初始化阶段。依据为本次会话中的原始需求及其后两次明确修订。
本文件替代旧方案中的“直连＋加密中继兜底”。旧 ChatGPT Space 页面没有在本次操作中被更新，不能作为当前实现基线。

## 一、定位与边界

构建五端主动文件互传产品：Windows、macOS、Linux、Android、iOS；优先自己配对的设备，后续支持其他用户。
文件按原始字节传输，不压缩、不转码、不自动打 ZIP。无商业限速和应用级大小/类型/总数量额度；实际受网络、磁盘、文件系统及权限限制。
首版支持普通文件、目录和空目录；不能假定所有系统均可打开任意格式，或完整保存其他系统的 ACL、扩展属性、符号链接。

双方在线且应用获得运行机会时传输。对方离线则保留本地队列，发送设备保留源文件；绝不上传到云端代存。
自有设备可信配对不强制注册账号。后续账号体系不破坏已配对设备的离线局域网使用。

## 二、网络原则

允许控制面：设备发现、在线状态、短期配对协调、候选地址交换、STUN 和 NAT 穿透协调。
禁止数据面：任何服务器或第三设备转发文件正文、密文块、可重构文件的编码片段、缩略图或用户文件副本。
更严格的隐私设计：文件名、目录清单、内容摘要和断点明细也只经已认证的设备直连交换。

局域网优先是实际路径策略，不是比较 SSID。Wi-Fi/有线/热点均以实际连通性、对端认证和平台接口证据判断。
本地探测可与公网准备有限并行，但文件正文不能抢先走未经批准的公网路径；仅局域网模式不连接公网协调设施。
公网尝试 IPv6/IPv4 候选连接及适用的打洞；无法直连则暂停/等待/重试，必要时解释网络隔离或建议用户选择其他网络。
NAT 类型不是绝对成功判据；不能承诺所有网络组合都成功，也不能把“STUN 成功”当作设备间连接成功。[S1][S2]

## 三、技术架构

推荐验证 Flutter UI＋Rust 共享核心＋原生平台插件＋SQLite 本机状态。网络库尚未冻结。
iroh/QUIC 为候选，但官方资料说明 relay 还参与连接建立和打洞，因此禁用 relay 后不能直接假设仍有同等穿透能力。[S3][S4]
P0 必须验证无 relay 的公网连接与独立信令协作；不通过则评估直接 QUIC＋独立穿透层，或无 TURN 的 WebRTC DataChannel。
不同时维护两套完整公网网络栈。已写入的 Rust 模型不代表网络库已选定或网络适配器已实现。

模块分为 DeviceIdentity、Discovery、Signaling、NatTraversal、DirectConnectionManager、TransferEngine、StorageAdapter、TaskStore、PlatformLifecycle 和 UI。
控制面服务没有文件上传/下载接口，也没有通用二进制转发接口。文件引擎仅能获得真实认证直连通道，不能获得服务器 HTTP 客户端。

## 四、体验

四个主要界面：设备；发送/接收；任务；设置与历史。
首次配对用二维码绑定设备密钥及短期配对信息，必要时双方核对；名称、地址和网络名不等于身份。
发送：选设备→选文件/文件夹→接收方确认→确认保存位置→直连传输→校验→最终保存。
进度明确区分扫描、连接、发送、校验、保存；只显示局域网直连/互联网直连/等待直连，不出现加密中继通道。
默认重名保留两份，覆盖必须明确选择。可信设备自动接收按设备单独启用，可撤销。

## 五、文件可靠性

64 位大小/偏移，固定内存预算，有限并发，边扫描边分页持久化目录清单。大量文件不等于大量线程。
块大小初始实验区间 1–8 MiB，最终以吞吐、重试成本和文件提供器能力决定，不作为文件上限。
采用成熟摘要实现进行块级验证和最终完整性校验；不自研密码算法。
接收端先可靠保存并检查，再确认检查点。恢复依据已落盘且验证的数据，不能以发送进度条为依据。
目录写入优先同目录临时文件与安全提交；不支持原子重命名的文件提供器采用可恢复的提交步骤，提前估算额外空间。

## 六、平台与原件

默认和单次保存位置分开设置。保存对象是授权目标，不总是文件路径；Android URI、iOS 书签需原生处理。[S6][S7]
图片/视频从系统获取原件而非预览或兼容转码。Live Photo 原件需保存关联资源；云端尚未下载的资源不能凭空在离线状态发送。
移动后台持续传输依赖目标系统机制和实际执行条件，不承诺永久常驻或被强制退出后继续接收。
五端最低系统版本、CPU 架构和 Linux 发行版必须 P0 冻结；不能以 UI 框架支持矩阵替代项目真实验证。[S5]

## 七、安全和约束证明

即便设备直连也必须认证加密；协调服务器受攻击不能替换已配对的可信对端身份。
服务器仍可见必要的 IP、在线时间等连接元数据，不宣传“完全看不见任何信息”。
无中继必须通过依赖配置、类型/接口边界、网络抓包、服务端入口检查和故障注入共同验证；单纯写 `relay=false` 不是证明。
用户自行配置的 VPN/透明网络转发可能在应用不可见层存在，不能绝对证明互联网路径没有其他服务器；应用不主动采用这类回退路线。

## 八、后续用户互传

分离 User、Device、TrustGrant。第二版首先做限时、可撤销、可限制次数的一次性邀请，再做账号与联系人。
邀请仅携带身份和连接授权，不携带文件字节。双方仍需在线并直连成功。
离线云端投递与第三设备代传永久不属于当前 ADR 下的路线；重新引入必须先变更用户明确确认的架构决策，不能作为普通技术选择。

删除中继部署和带宽预算不代表开发一定缩短，穿透诊断和无中继证明的工作增加。

首个完整里程碑：无外网局域网中 Windows↔Android 安全配对、选择目录、传输 >4 GiB 文件、断网恢复、最终摘要相同；同期 iPhone 真机最小收发与授权/后台实验。
