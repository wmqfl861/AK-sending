## 7. C4 真机实测方案（修订交接 §8）

### 7.1 前置条件（缺一不测）

1. CR-P1-05 已完成，CI 的 NAT 矩阵测试通过。否则端口受限锥形的组合大概率失败，等于白测。
2. GUI 能导出连接诊断：候选类型、是否拿到反射地址、实际成功的路径类型、各阶段耗时。这对应交接 §6 的提案 4（`probe_observed` 事件）。没有它，手机端失败时无从定位。导出内容只保存在本地。
3. 所有者已完成 E6 的部署，线上服务端与客户端是同一版本；否则测到的是旧服务端。

### 7.2 设备组合

| 组 | 组合 | 说明 |
|---|---|---|
| A（必测） | 家宽电脑（Windows）↔ 手机移动数据（Android） | 分"只用 IPv4""只用 IPv6""双栈"三种条件各测一次。手机可在接入点设置里切换协议，电脑可在网卡属性里临时关掉 IPv6 |
| B（必测） | 两个不同家宽 | 电脑 ↔ 电脑，或电脑 ↔ 连着另一家 Wi-Fi 的手机 |
| C（对照） | 同一局域网 | 确认局域网优先仍然生效，建连耗时没有退化 |
| D（可选） | 手机热点 ↔ 家宽；校园网或公司网 | 有条件就测 |

### 7.3 每组记录什么

写进 `docs/TEST_PLAN.zh-CN.md` 的**只能是分类信息，不写真实 IP**（`AGENTS.md` 禁止把完整网络诊断写进仓库；交接 §8 第 3 步要求记录两端地址，这一条要改掉）：

- 两端 NAT 的映射行为与过滤行为（可以用 NatTypeTester 这类支持 RFC 5780 的工具测）、是否处在运营商级 NAT（100.64.0.0/10）、有没有全局 IPv6；
- 成功路径的类型（局域网 / IPv4 反射地址 / IPv6 全局地址 / 观测地址）、建连耗时、不小于 100 MB 文件的吞吐，以及两端 SHA-256 是否一致；
- 每组至少测 3 次，记录成功次数；失败时检查 UI 文案是否符合 E3。

### 7.4 无中继证据

在一端抓包（Wireshark 或 tcpdump），按远端地址统计传输期间的字节数：文件数据只能出现在对端地址上；与服务器之间只有 TCP 7200 和 UDP 7101 的少量控制流量。原始 pcap 只保存在本地，仓库里只写统计结论。

### 7.5 判定标准

- 端口受限锥形及更宽松的 NAT 组合、两端都有 IPv6 的情形：必须成功。
- 有对称 NAT 参与的组合：允许失败，但必须给出 E3 文案，界面不能卡住。
- 任何一组出现服务器转发文件数据：立即判为 **P0**。
