# Claude 审计采纳裁决 — 2026-11-02

审计原文：[REVIEW_2026-11-02](REVIEW_2026-11-02.zh-CN.md)。基线 `eed9fc96d88725a18aad69aa61d4151583fd295b`。用户要求独立决定采纳并给出最终蓝图，本次不再要求用户逐一确认 D1–D6。

| 事项 | 裁决 | 原因和补充 |
|---|---|---|
| D1：排除 iroh，QUIC + 独立协调 | 采纳选型，修正绝对表述 | iroh 能禁 relay，但原生穿透协调围绕 relay；不是“所有无 relay 场景不能用”。为约束可审计与少维护，首版不引入它；主栈 quinn/rustls |
| 自建打洞层 | 有条件采纳 | 自有的是协调/适配，不从零手写密码学或完整 ICE；同 UDP 端点的分流、身份、事务、角色与重传必须实测 |
| D2：接受直连失败 | 采纳 | 保持 ADR-001，清晰解释失败；外部 70% 测量不能转为本项目成功率承诺 |
| D3：端口映射 | 部分采纳 | 默认关闭、可信网络用户启用、短租约、仅本机端口；PCP/NAT-PMP 先行，UPnP 按实测收益后置 |
| D4：精简文档 | 采纳并保全历史 | 五个规范主入口，旧拆分页变索引；原审计和报告不删除、不重写 |
| D5：先 CLI 再 UI | 采纳但前置手机实验 | 最小移动构建/目录/后台与 LAN 原型并行；不等全部桌面产品完成再发现 iOS 阻塞 |
| D6：类型/依赖/行为约束 | 采纳并明确证明范围 | 私有类型构造+接收授权+依赖特性审查+服务协议负例+断路抓包；cargo-deny 不能仅靠名称证明无中继 |
| IPv6 优先/交换内网候选 | 采纳并修正 | IPv4 并行避免 IPv6 黑洞；同出口不等于同 LAN，候选仅给授权对端 |
| Android 默认 MediaStore | 暂不作为默认双轨 | 首版通用目录以 SAF 为基线；MediaStore 吞吐与完整目录语义实测通过才增加，降低双实现维护 |
| Flutter + Rust | 采纳 | 五端统一 UI、原生能力仍独立适配；不以未测结论宣称 Tauri 一定不适合 |
| 边写边哈希 | 采纳，保留恢复重读 | 正常连续传输免默认二次全读；进程崩溃需重建摘要并核验落盘块，不能用块哈希拼接冒充整文件哈希 |
| WebRTC 与“不限速冲突” | 不采纳该推论 | 协议开销不是产品限速；暂不选它是范围与单栈决策，不声称任何场景必定比 QUIC 慢 |
| 禁 UDP 则全部直连不可能 | 不采纳该泛化 | 只报告当前 QUIC 版本不可用；TCP+TLS 直连可另评估，首版不并行做两套 |
| 信令+STUN 一个小服务 | 采纳 | 单部署、多端口、逻辑隔离；使用成熟协议实现，不为了轻量自己发明 STUN |

最终要求见 [蓝图 v0.2](BLUEPRINT.zh-CN.md)，执行与验收见 ROADMAP、TEST_PLAN。技术依据列于蓝图 R1–R13。
