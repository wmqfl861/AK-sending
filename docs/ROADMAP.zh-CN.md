## M1：安全的局域网命令行原型

- [ ] `ak-cli` 支持配对、发送、接收、目标目录、进度和取消；CLI 复用未来 GUI 的同一核心。
- [ ] 先手动地址/完整配对邀请，再加原生发现；不因发现尚未完成阻塞验证真正数据通道。
- [ ] >4 GiB 单文件原始字节流、BLAKE3 增量摘要、接收确认、临时写入和保存完成回执。
- [ ] 文件夹/空目录、分页清单、重名保留、路径逃逸防护、初步 SQLite 检查点和断网继续。
- [ ] 手机 2 / 桌面 4 的初始文件并发，受全局缓存预算统一调节；测文件句柄和队列峰值。
- [ ] 与上面并行完成首组公网实验：同 UDP 端点的 STUN/检查/QUIC 分流、IPv6/IPv4、跨两个真实网络，不使用中继。
- [ ] 与上面并行验证 Android 离线任务网络条件及 iOS 前台/后台中断；结果写入真机报告。

退出门槛：真实双机断外网传输 >4 GiB 且内容一致，拒绝错误对端，断网恢复不从头无故重传；手机适配结果已记录。单机 loopback 不替代双机验收。

## M2：公网直连与可靠恢复

- [ ] 一个协调程序：有认证的窄信令和 STUN Binding，内存 TTL 会话，不接收文件清单/哈希/正文。
- [ ] 采用成熟 STUN/ICE 组件完成候选收集、角色/事务/重传、选择；过滤 relay，网络变化重新验证。
- [ ] IPv6 优先但不阻塞 IPv4；内网候选仅在已授权会话交换；相同出口不是局域网判据。
- [ ] 可选 PCP/NAT-PMP，默认关闭；短租约、限定本机端口和退出清理。UPnP-IGD 仅在验证收益后加入。
- [ ] 杀进程/重启/检查点不同步/磁盘满/目录撤权/源文件变化恢复；丢失完成回执时幂等确认。
- [ ] 接收文件有效前缀重读与摘要状态重建；不得以“零重读”为代价跳过内容验证。
- [ ] 保留信令、切断设备数据路径：进度停止，服务器不替代传输；候选注入/网络重绑定负例通过。
- [ ] 输出可复现的公网网络组合矩阵与失败诊断，成功率使用本项目数据与完整分母。

退出门槛：跨网成功和失败均有证据，断路时无服务器回退，可靠恢复与隐私边界通过。没有公网成功证据不能宣布互联网功能可用。

## M3：Windows + Android 可用 GUI

- [ ] Flutter 四个主界面、拖放/系统文件选择、默认目录、单次改选、配对管理。
- [ ] FFI 只传指令/句柄与聚合事件；大文件不绕行 Dart；目录列表虚拟化。
- [ ] Android SAF 基线、原件导入、UIDT 或适用前台机制、通知与网络绑定；MediaStore 先做专项对比。
- [ ] 无账号离线 LAN、可信设备授权接收、明确连接方式/等待原因、移动数据默认不允许。
- [ ] Windows/Android 的包体、空闲/活动内存、启动、CPU 和吞吐报告。

退出门槛：两端可用交互和真实传输矩阵通过，资源预算明确达标或有审查后的调整；不能只有漂亮 UI。

## 执行规则

每个模块强制先单独提交 `docs/modules/<编号>_PLAN.zh-CN.md`，再开发、实际测试、审核、修复复测、交接；审核报告绑定实现 SHA。规则详见 AGENTS.md，不能以整个大阶段代替可审查的小模块。

按单维护者 + AI 的小规模流程组织。先 M0/M1 的可运行提交，再推进公网与 UI；网络和手机风险实验可并行，不创建互相竞争的主分支写入者。
每次交接只写：基线 SHA、修改范围、已执行命令/结果、未测项、下一任务。历史测试日志不改写成新提交的结果。
旧 20–28 周估算保留为历史而非现行排期；M1/M2 完成后据真实吞吐与平台成本估算。没有发布、部署或费用支出的默认授权。
