# 用户体验与界面行为

设备：已配对设备、在线/可达状态、添加/撤销、名称编辑。在线不等于可直连。
发送：设备→普通文件/文件夹/相册原件→确认→接收授权。扫描可取消，边扫描边反馈。
接收：显示可信发送设备、任务规模、目标位置、空间状态和重名规则。默认确认，逐设备可启用自动接收。
任务：扫描/等待授权/连接/传输/暂停/等待设备/校验/保存/完成/失败/取消。
设置：默认保存位置、每次询问、可信自动接收、仅局域网、蜂窝网络授权、托盘/通知与日志管理。

通道显示只有“局域网直连”“互联网直连”“等待直连”。不提供中继开关，也不提供“加速服务器”入口。
公网直连失败：明确写“当前网络无法建立设备直连，文件没有上传到服务器”，提供重试及网络检查说明。
网络从 Wi-Fi 切到蜂窝时遵守已授权策略；不因用户曾允许局域网而默认允许移动数据。
校验/最终保存未完成时不能显示接收成功；多文件任务区分全部成功、部分成功、失败和取消，保留逐文件结果。
历史记录与文件本体分别管理；取消任务清理临时文件的策略明确，不误删已完成文件。

## CLI 原型已实现的交互（2026-11-03 现状）

以上是目标 UX 设计；本节记录命令行原型（ak-cli）当前的实际交互，二者并行存在，冲突处以"现状注记"对冲、不修改上文。

### 配对流程（准入三形态）

- 配对码：`pair code` 显示本机指纹与 6 位配对码；`receive --expect 123-456` 只接受配对码匹配的对端（分隔符可省略或宽松摆放，按指纹推导配对码比对）。
- 指纹：完整 64 位十六进制，或 8–63 位唯一前缀（查本机配对簿补全）；零命中与多命中都是显式报错，多命中时列出候选短 id 提示补齐字符。
- 配对簿准入（默认形态）：`receive` 省略 `--expect` 时只接受 peers.book 内的指纹；簿为空则拒绝启动并打印配对指引；每个连接都重读配对簿，`pair add` 免重启即时生效。`--expect any` 显式放开并打印"接受每一个对端"的警告。
- 发送端信任首次使用（TOFU）：`send` 成功后自动把接收端指纹记入配对簿；`send --fp` 同样接受完整指纹或唯一前缀。

### 接收循环行为

- 默认一个任务完成后继续等待下一个发送方，Ctrl-C 停止且已落盘部分保持可续传（.akpart 分片 + 检查点）；`--once` 只处理一个任务后退出。
- 准入策略之外的对端被拒绝时打印一行提示并继续等待，不中断循环。
- 重名策略 `--conflict error|rename`（默认报错）；`--timeout` 为帧间空闲预算（默认 30 秒，非总运行时长），适用于循环的每一轮。

### 进度渲染

- 字节级进度单行刷新：每 16 个确认块更新一次（`BytesAcked` 事件），`\r` 回刷、79 列裁剪加填充擦除，不刷屏。
- 文件级事件（开始：路径+大小 / 提交）与任务级事件（连接、发起、接受、恢复、暂停、最终确认、完成）整行打印；打印前先擦除未闭合的进度行，保证日志可读。
- 环境变量 `AK_QUIET` 静默全部进度输出；接收端首次监听打印地址、指纹、配对码与 Windows 防火墙提示文案。

### 错误文案现状

- CLI 输出为英文；已有少量带行动指引的映射：指纹前缀不在簿内/歧义时给出补齐或改用全指纹的建议，多路径重名时建议分开发送，配对簿为空时给出完整配对步骤。
- 系统性友好错误映射（含中文文案与统一术语）开发中，落地后本节更新。

### doctor 定位

- 环境自检/诊断子命令 `doctor` 开发中；落地后将在此补充其检查范围与输出说明。

### 现状注记（与上文设计的关系）

- 上文"接收：默认确认，逐设备可启用自动接收"：现状为连接前准入策略（`--expect` 三形态），无逐任务确认 UI。
- 上文"任务：扫描/等待授权/连接/传输/暂停/等待设备/校验/保存/完成/失败/取消"完整状态机：现状仅暴露进度事件子集（连接/发起/接受/逐文件开始与提交/暂停/恢复/最终确认/完成），无失败/取消的独立面板态。
- 上文"设置：默认保存位置、每次询问……"：现状以命令行旗标承载（`--out`/`--conflict`/`--timeout`），无持久化设置。
- 上文"通道显示只有局域网直连/互联网直连/等待直连"：现状通道分类存在于网络层（classify），CLI 输出尚未将其渲染为这三种用户态标签。
