# ADR-001：仅设备直连承载文件数据

状态：**Accepted（用户明确确认）**。范围：所有平台、所有后续版本、所有运行配置。

## 决策原文

> 允许服务器参与设备发现、信令和 NAT 穿透协调，但绝不允许任何服务器参与文件数据传输，包括加密中继。

## 允许与禁止

| 类别 | 决策 |
|---|---|
| 设备发现、在线状态、身份/配对协调 | 允许，最少必要信息 |
| 公网地址发现、STUN、打洞调度 | 允许，仅连接控制 |
| 经认证的端点间直连 | 唯一可承载文件的通道 |
| TURN、iroh relay、第三方中继 | 禁止，包括密文、分块和编码片段 |
| HTTP/WSS 上传下载文件、云端暂存 | 禁止 |
| 信令通道传输文件/缩略图/预览/文件清单 | 禁止 |
| 系统自动改走数据代理或第三设备代转 | 禁止 |
| 连接失败时等待/重试/用户换网 | 允许 |

## 术语与承诺边界

“服务器”是通信两端以外的应用层服务/转发节点，包含自建、第三方、用户自建 VPS 和作为代传者的其他设备。
接收方自己选择的电脑/NAS 可成为未来受认证的目标端点；它不能假扮中继为其他接收方代存。
普通网络路由器、交换机及 NAT 不属于产品部署的数据中继。无法仅靠客户端证明用户 VPN/透明代理/运营商物理路径中不存在第三方机器。
产品可审计承诺为：不主动建立、配置或回退到任何应用层服务器文件数据路径，并拒绝可识别的非直连路径。
不接入云盘文件提供器作为隐式投递后门；用户自行选择云盘目录产生的系统同步必须明确告知，这不是本项目数据通道。

## 强制要求

- INV-001：文件数据面只连接已配对/本次明确授权的最终接收设备。
- INV-002：未知路径、relay 路径、身份不符、未认证或未加密路径一律拒绝发送文件。
- INV-003：本地认证连接可用时优先本地；探测尚未结束时不盲目优先公网。
- INV-004：更换网络、候选地址或底层连接后重新检查身份和路径，合格前暂停正文。
- INV-005：协调协议无文件 payload、任意 blob、文件名、清单或内容哈希字段；不提供上传接口。
- INV-006：仅局域网模式不访问公网发现、STUN、信令；仍允许离线配对与互传。
- INV-007：服务器退出后既有稳定直连不应因为应用设计被主动断开；网络重绑定可能需要重新协调。
- INV-008：禁止以性能、重试、兼容、诊断或未来邀请功能为由启用数据中继。

短期配对签名、握手参数、连接候选是控制数据，可以经服务器。固定字段、大小/频率限制只能降低误用，不声称杜绝恶意用户通过任意字段制造信息隐写。

## 后果

接受某些网络组合无法连接；不承诺所有对称 NAT 必然失败或任何 NAT 类型必然成功。
无中继文件带宽成本，但控制服务、鉴权、反滥用和诊断仍有成本。
保留终端端到端认证加密。将“服务器不转发文件”与“服务器完全看不见元数据”区分。

## 验证

必须证明局域网/公网路径；强制阻断对端数据连通性而保留信令时，文件进度必须停止，不能改走控制端口。
捕获服务器出入站，检查所有服务接口和客户端依赖默认行为；将传输大小与控制流量增长进行对照。
没有真实抓包、双端实验和库配置审计时，只能报告设计符合，不能报告已证明无中继。
