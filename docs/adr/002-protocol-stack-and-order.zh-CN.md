# ADR-002：采用"QUIC + 自建信令/打洞"路线与先局域网原型的推进顺序

- 状态：已接受（2026-11-02，项目所有者指示"继续本地开发，多模块并行，直到项目完成"）
- 关联：ADR-001（直连约束，不变）；docs/REVIEW_2026-11-02.zh-CN.md 的 D1、D5、D6 建议

## 背景

方案评审（2026-11-02）提出 D1–D6 待确认决策。所有者随后指示继续本地开发、多模块并行推进、完成前不推送。该指示被理解为：采纳评审第五节"单人＋AI 推进顺序"，按 D5 顺序实施，网络路线按 D1 收敛，约束机制按 D6 落地。

## 决策

1. **网络路线（D1）**：排除 iroh（打洞依赖 relay，与 ADR-001 冲突）。数据面 = QUIC（quinn）+ rustls（ring 后端）+ 自签 Ed25519 证书 + 指纹钉扎；控制面 = 自建信令（TCP，定长有界消息）+ 内置最小 STUN（RFC 5389 子集）。禁用 TURN/relay/HTTP 上传，无任何回退中继。
2. **推进顺序（D5）**：先局域网 Rust 命令行原型（含配对、断点续传、摘要校验、>4 GiB 稀疏文件测试），再公网直连探测工具（信令 + STUN + UDP 同时打开 + 握手验证），Flutter 五端界面后置。
3. **约束机制（D6）**：以代码结构替代 architecture.json 硬编码比对：
   - 类型约束：`AuthenticatedDirectChannel`（`ak-net::DirectChannel`）无公开构造函数，仅由握手并通过指纹校验的内部路径产生；`ak-engine` 只接受该类型。
   - 依赖约束：仓库检查脚本解析 Cargo.lock，禁止 relay/TURN/WebRTC/iroh 类 crate 进入依赖图。
   - 服务端约束：信令消息集合为封闭枚举、无 payload/blob 字段，由单元测试锁定；无任何文件上传/转发路由。
   - 行为约束：集成测试模拟"信令在、数据路径断"（错误钉扎/对端消失），断言进度停止且不回退（TEST_PLAN T04 的自动化形态）。
4. **模块拆分**：ak-core（领域模型）、ak-identity、ak-wire、ak-storage、ak-net、ak-discovery、ak-store、ak-signal、ak-engine、ak-cli。各模块可独立编译测试，接口契约先冻结再并行开发。
5. **依赖引入**：从零第三方依赖放宽为受控清单（tokio、quinn、rustls、ring 系、ed25519-dalek、blake3、rcgen、mdns-sd、if-addrs、clap 等），全部为纯 Rust 或 MSVC 可编译，无 relay 类依赖；任何新增依赖需对照 ADR-001 复核。

## 后果

- 公网直连成功率预期沿用评审 4.1（约 70% 量级、无中继兜底）；失败即暂停/重试并给可操作建议。
- IPv6 优先、同出口内网候选优先、路由器端口映射（D3）暂不默认开启；端口映射留待所有者另行确认后在探测工具中启用。
- 本地原型验证为 L2 层级（真实 QUIC 收发、真实文件系统）；真机、跨网、抓包（L3/L4）仍未完成，状态如实标注。
- 若后续所有者对 D1–D6 有不同选择，本 ADR 可回退；回退时需重估 ak-net/ak-signal 的实现投资。
