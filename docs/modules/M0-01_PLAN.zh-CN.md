# M0-01 开发计划：工程基线与接收授权状态机

状态：PLANNED。日期：2026-11-02。此计划先于实现提交。
基线：`f34140f75c54e0de28f45856ef41aa9750e1aaf2`（蓝图 v0.2 分支，PR #1 未合并）；main 读取值 `eed9fc96d88725a18aad69aa61d4151583fd295b`。不自动合并 PR #1。

## 目标与非目标

这是 M0 的第一个可独立审核子模块，不是整个 M0 完成。
目标：固定 Rust 工程基线，补齐接收授权与撤销/恢复状态，建立实际命令结果和后续模块审核流程。
非目标：本次不实现 quinn/rustls 网络、密码学身份、真实目录写入、NAT、Flutter、手机后台或完整续传。接收授权模型不是认证连接，不能据此宣布安全文件传输已实现。

## 实施范围

1. 固定 Rust 工具链、Cargo.lock、rustfmt 配置和最低 Rust 版本；当前领域 crate 维持零第三方运行时依赖。Flutter 与网络依赖到各自模块引入时固定，不添加空壳依赖。
2. 为 job.rs 增加 AwaitingConsent / Rejected，以及直连重建后重新授权、拒绝、取消、授权撤销和已完成状态保护。连接准备好不再直接进入 Transferring。
3. 引入接收任务控制器，状态字段私有；接收许可绑定任务、对端和连接代次，使用单调时间有效期。在暂停、断连、撤销和终止时清除许可；错误身份、过期许可或旧连接不能恢复传输。它只负责领域授权，不验证真实网络或证书。
4. 对文件写入与完成判定设计显式检查点：未许可不能进入传输；收完不等于完成；内容校验后仍需可靠保存回执。验证/保存中不开放重新传文件的旁路。
5. 修正仓库静态检查的执行范围描述。新增测试执行器，逐项记录命令、退出码、耗时、stdout/stderr、代码树标识；缺少工具明确 skipped，必须命令未通过时整体失败。
6. 添加最小 CI（Linux / Windows / macOS 核心测试），contents:read、无 secrets、无部署、无发布；Action 固定 SHA，不引入缓存/大型矩阵。CI 验证领域核心而非五端产品。
7. 更新 README、ROADMAP 的子模块状态和 HANDOFF。保存审核记录、证据清单并刷新 MANIFEST。

## 接口与安全边界

现有 State::advance 是可复制的纯状态模型；保留其模型用途，禁止把枚举值当安全许可。新增接收任务控制器是未来文件引擎接入点，不能公开设置其状态。
M0-02 必须额外提供只能由真实握手生成的 AuthenticatedDirectConnection。M0-01 不接受调用方布尔值作为密码学验证，也不宣称实现了私有认证连接类型。
文件任务授权由接收侧 UI/策略产生；远端消息必须由可信协调层解释，不能将网络字段直接映射为用户同意。许可不序列化、不跨进程恢复；重启后重新授权。

## 测试与验收

A1：旧分块/纯直连策略测试不回退；默认无第三方依赖。
A2：DirectReady 只到 AwaitingConsent；没有同意不能进入 Transferring；拒绝是终态。
A3：同意绑定任务/对端/连接代次，过期、错任务、错对端、旧代次均拒绝；过期边界为 now >= expires_at。
A4：暂停、断连、撤销、取消、失败清除许可；恢复必须重新连接和授权；终态不能复活。
A5：AllBytesReceived → Verifying → Saving → Completed，不允许跳过校验或可靠保存；非法事件不改变状态。
A6：状态转换表穷举测试；控制器错误路径和重复事件测试；公开 API 的外部集成测试。
A7：真实执行 Rust fmt / test / clippy 与 Python 测试；报告包含执行范围，模拟测试不能冒充 Rust 编译。
A8：执行器对成功、失败、缺少程序和超时分别有测试，失败仍保存证据；测试无外网依赖。
A9：审核计划与实现的一致性、授权边界、资源分配、日志隐私和测试缺口。修复后复测，不隐去首次失败。

## 执行顺序与完成门槛

先提交本计划和项目规则；再开发与测试；再对实现 SHA 做实施者复核，记录发现并修复，最后提交审核/交接。无法实际运行 Rust 时尝试授权的 GitHub CI；仍不可执行就交付 PARTIAL 并保留未测状态，不能假称通过。
本模块可在核心测试与审核完成后结束；真实跨设备连接、>4 GiB、手机和公网实验仍属后续模块，不据此勾选整个 M0。

## 风险及回退

状态枚举新增可能破坏调用方；当前无网络/UI 调用方，使用外部集成测试锁定预期。时间检查使用进程单调时钟而非不可信墙钟；授权不能持久化。
CI 初始化可能受 workflow 权限/runner 限制，不绕过权限；原始日志保全。多执行者并发时使用新分支，ref 更新失败先重读，不强推。
回退仅回退本模块实现提交，保留本计划与用户项目规则，不重写基线或 Claude 审计历史。
